## Context

AI Daybook은 한국어 지면만 낸다. 해외 독자를 받으려면 영어판이 필요하고, 영어로 검색했을 때 노출돼야 한다. 현재 상태를 점검한 결과는 다음과 같다.

| #   | 현재 상태                     | 영어판·영어 검색에 미치는 영향 (근거)                                                                                                                                                                                                         |
| --- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 본문이 한국어뿐이다           | Google은 검색어 언어와 **본문 언어**를 맞춘다. 영어 검색어와 맞을 내용이 없다. 2026-11 SEO 작업에서는 제목·설명에만 영어를 병기했다(`src/lib/site.ts` `SITE_TITLE`·`SITE_DESCRIPTION`).                                                       |
| 2   | 언어 신호가 모두 `ko`다       | `<html lang="ko">`가 최상위 레이아웃에 고정돼 있다(`src/app/layout.tsx`). `og:locale ko_KR`, JSON-LD `inLanguage: "ko"`도 같다. hreflang은 없다.                                                                                              |
| 3   | UI 문구가 하드코딩돼 있다     | 약 25개 파일에 한국어 문자열이 있다. 많은 순으로 `Edition.tsx` 60줄, `Story.tsx` 43줄, `FeedView.tsx` 38줄, `ArticleMeta.tsx` 34줄, `Masthead.tsx` 29줄. 날짜 표기(`formatLongDate` 등)와 분야 표시명도 한국어 전용이다(`src/lib/labels.ts`). |
| 4   | 가공 출력이 한국어 필드뿐이다 | `articleEnrichmentSchema`는 `title_ko`·`summary_ko`·`category`·`tags`만 받는다(`scripts/lib/schema.ts`). 기사당 출력 예산은 350토큰이다(`scripts/lib/enrich.ts` `MAX_OUTPUT_TOKENS_PER_ARTICLE`).                                             |
| 5   | 한국 매체 기사가 차별점이다   | 게재 1,232건 중 **380건(31%)**이 한국 매체 원문이다(AI타임스·전자신문·바이라인네트워크·로봇신문 등). 해외 AI 뉴스 서비스가 거의 다루지 않는 영역이다. 반면 소스에는 지역·영문명 정보가 없고, 매체명이 한글이다.                               |

**목표:** 같은 호를 영어로도 발행한다(`/en/`). 영어로 검색한 사람에게는 영어판이, 한국어로 검색한 사람에게는 한국어판이 노출되게 한다. 한국어판의 화면·URL·색인은 바꾸지 않는다. 회차 비용은 $0.1 상한 안에 둔다.

## 확정된 결정 (2026-11-03 사용자 확인)

- **편집 = 같은 호 + 한국발 강조.** 영어판은 한국어판과 같은 기사·같은 1면을 쓴다. 영어판 선별을 따로 두지 않는다. 대신 한국 매체 기사에 `KOREA` 표시를 붙이고, 1면 아래에 **Korea Desk** 밴드를 둬서 해외 독자에게 차별점을 보여준다. 추가 LLM 호출은 없다.
- **지난 기사 전체 백필.** 게재된 기사 전체(약 1,232건)의 영어 제목·요약을 1회 생성한다. 예상 비용은 약 $0.6이고 상한은 $1로 둔다. 출시 첫날부터 영어판 지난 호·기사·사이트맵을 다 갖춘다.
- **주소는 github.io 유지.** `https://sguys99.github.io/global-ai-news/en/...`을 쓴다. 커스텀 도메인 전환은 Phase 9 선택 항목으로만 남긴다.

## 아키텍처 결정 (전 Phase 공통)

- **영어 본문은 가공 단계에서 같은 호출로 만든다.** `enrich` 출력에 `title_en`·`summary_en`을 추가한다. 한국어 요약을 다시 번역하지 않고 **원문에서 직접** 쓴다(원문의 69%가 영어다). 호출 수는 그대로이고, 회차당 비용은 약 +$0.01로 예상한다.
- **영어 작성 규칙은 한 곳에서 관리한다.** `configs/prompts/english.md`(문체·고유명사·숫자 규칙)와 `configs/prompts/glossary.en.md`(한국 기관·기업 영문 표기)를 가공 프롬프트와 백필 프롬프트가 함께 쓴다.
- **선별·재보도 검사·같은 사건 합치기·세 줄 요약 선택은 한국어 기준 그대로 둔다.** 영어판은 그 결과를 따라간다. 영어 세 줄 요약은 같은 줄 id의 `title_en`을 쓴다(추가 호출 없음).
- **소스 속성으로 지역을 둔다.** `configs/sources.json`에 `region`(`kr` | 생략)과 `nameEn`(영문 매체명)을 두고 `sources` 테이블에 동기화한다(`format`과 같은 방식). Korea Desk와 `KOREA` 표시는 LLM 비용 없이 이 값으로 정한다.
- **라우트는 언어별 최상위 레이아웃으로 나눈다 — 1안 확정(2026-11-03 Phase 0-2 스파이크).** `src/app/(ko)/layout.tsx`(`lang="ko"`)와 `src/app/(en)/en/layout.tsx`(`lang="en"`)를 두고, 앱 전체 404는 `src/app/global-not-found.tsx`가 맡는다. 이 파일은 `next.config.ts`의 dev·프로덕션 분기 **둘 다**에 `experimental.globalNotFound: true`가 있어야 동작한다(Next 15.5.15). 페이지 본문은 `src/views/*`로 옮겨 두 언어가 공유하고, 사이트맵·RSS·OG·api 라우트 핸들러와 아이콘은 그룹 밖 `src/app/`에 그대로 둔다. 스파이크에서 정적 export 확인 5개(lang·404·sitemap/feed/og·dev admin·basePath)를 모두 통과했고, 한국어 페이지 본문 마크업은 기준선과 같았다. 2안(단일 레이아웃 + 영어 래퍼 `lang="en"`)도 빌드해 비교했다. 용량이 똑같이 늘고(+4%, 페이지당 약 +5KB — 레이아웃 단계가 하나 늘어나며 생기는 비용) 정적 HTML이 `lang="ko"`로 남아서 기각했다.
  - **404는 한 장뿐이다**(GitHub Pages·nginx). 404 페이지에 두 언어 문구를 함께 싣고, `/en/` 경로에서는 인라인 스크립트로 `lang`을 바꾼다.
  - `global-not-found`는 레이아웃을 거치지 않는다. viewport·헤더·모바일 바·푸터·ThemeProvider·Analytics를 직접 넣어야 하므로, 두 레이아웃과 404가 공유하는 `fonts.ts`와 공용 셸 모듈로 모은다.
  - 언어를 넘는 이동은 전체 새로 고침이다(루트 레이아웃이 다르다). 언어 전환 링크는 `prefetch={false}`를 검토한다.
  - 영어 레이아웃에도 `metadataBase`·소유 확인 메타를 넣는다.
  - 실험 기능에 기대므로 Next를 올릴 때 404부터 확인한다. 기능이 깨져도 빌드는 성공하고 404만 기본 화면으로 퇴보한다.
  - 상세: [phase0/0-2-routing-spike.md](english-version/phase0/0-2-routing-spike.md)
- **UI 문구는 사전으로 관리한다.** `src/lib/i18n.ts`에 `Locale = "ko" | "en"`, 문구 사전, `localePath()`를 둔다. 분야·형식 표시명과 날짜 포맷은 기존 단일 출처인 `src/lib/labels.ts`에 영어 버전을 더한다.
- **한국어판은 바뀌지 않는다.** 구조를 바꾼 뒤에도 한국어 페이지의 HTML이 바뀌지 않았는지 비교해서 확인한다(Phase 3).
- **불변:** 정적 export·GitHub Pages·Batches 호출 계층·비용 상한 $0.1·DESIGN.md 톤(뉴스프린트·잉크·코발트 단일 강조·괘선)은 그대로다.

## Phase 4: 사이트 용량 대책 (영어판 출시 전 필수)

영어판을 출시하면 페이지가 두 배가 된다. GitHub Pages 한도는 1GB다(초과하면 배포 실패나 경고). 0-4 측정 결과, 페이지 크기 목표 하나로는 2년을 버틸 수 없다. 영어판을 더하면 하루 5.89MB씩 늘고, 2년간 700MB 이하로 두려면 기사 1건이 8~10KB여야 한다. 그래서 출시 전 경량화(1단계)와 출시 후 보관 등급(2단계)으로 나눈다. 0-2 스파이크의 레이아웃 분리로 페이지당 약 +5KB가 더 붙는 것도 계산에 넣는다.
