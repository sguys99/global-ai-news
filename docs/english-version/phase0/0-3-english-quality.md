## 요약

- **산출물(저장소, 커밋 안 함):** `configs/prompts/english.md`(영어 작성 규칙, 1,579토큰) · `configs/prompts/glossary.en.md`(한→영 표기 사전, 3,212토큰, 이름 약 150개 + 성씨 41·계급 6).
- **샘플 20건** — 최근 3개 호(11-01~11-03). 한국 매체 10(AI타임스 4·전자신문 2·로봇신문 3·바이라인 1), 영어 매체 10(뉴스 6 — 그중 HN 본문 없음 1·링크만 1, 오픈소스 2, 논문 2). **모델 형식 기사는 DB에 한 건도 없어** 넣지 못했다(hf_models 게재 0건).
- **결과:** 1차 OK 7 · 경미 11 · 오류 2 → 규칙 개정 후 2차 OK 17 · 경미 1 · **오류 2**. 1차 문제 유형 대부분(논평 덧붙임·주장 단정·완료/진행 혼동·파생 수치·계급 오역·인명 음절 누락·repo 주체 뒤집힘)은 2차에서 사라졌다. 2차에 **새 오류 2건**이 나왔다: 한국 원화 단위(10억 → KRW 100 million)와 주체 바꿔치기(스윙 → 본문의 쏘카). 같은 입력에서 1차는 둘 다 맞혔다 → Haiku의 **회차 간 변동**이라 규칙만으로 0이 되지 않는다. 앞의 것은 숫자 검사가 잡고, 뒤의 것은 코드 검사로 잡기 어렵다.
- **한글 유출 0/40.** 제목 길이 46~97자(전부 ≤100). 요약 8~47단어 — 40~60단어 목표는 본문이 짧은 기사에서 자주 못 미친다(정상; 길이 검사는 넉넉히).
- **원문 기반 작성이 맞다는 근거:** 기존 한국어 가공본에 단위 오류가 있는 기사에서 영어는 정확했다 — 1301 `$900B` → KO "900억 달러"(실제 9,000억 달러) / EN "$900 billion", 1321 `27B` → KO "27억 파라미터" / EN "27B". DB 전체에서도 KO 쪽 billion→억 10배 오류가 다수 보인다(아래 부록).
- **숫자 검사 오탐률:** 단순 규칙(쉼표 제거 + 문자열 일치, brief.ts `numbersIn` 방식)은 **정상 39건 중 3건(7.7%) 오탐**, 원화·달러 단위를 값으로 환산해 비교하면 **0/39(0%)**, 진짜 오류 1건(1324 2차)은 모든 변형이 잡았다. 39개 경계 사례 표에서도 최종 규칙은 0건 오분류.

### Phase 1-3 권장 규칙

1. **숫자 추출:** `/\d+(?:[.,]\d+)*/`, 쉼표 제거, 수치로 비교(`98.90 = 98.9`, `04 = 4`). 하이픈으로 붙은 수(`27-year-old`, `26B-A4B`, `GPT-5.1`)는 이것만으로 맞는다.
2. **금액·규모를 값으로 환산(필수 — 없으면 한국 매체 오탐 약 8%):**
   - 한국어: `[숫자][십|백|천]?[만|억|조]`를 이어 붙여 합산. `9억 2천만` = 9.2e8, `32만 4천` = 324,000, `2만5000` = 25,000, `1,550억` = 1.55e11. 단독 `천`은 뒤에 한글이 오면 단위가 아님(`천안`) — 단 `천여/천개/천명/천건/천원/천대/천곳`은 단위.
   - 영어: `[숫자][\s-]*(thousand|million|billion|trillion|bn|mn)` 또는 붙여 쓴 `K/M/B/T`(`27B`, `$62.5M`; `5 m`처럼 띄운 한 글자는 제외).
   - 출력의 숫자가 원문에 그대로 없으면 그 숫자가 속한 금액의 값이 원문 금액(또는 원문 일반 숫자)의 값과 같은지 본다. 단위 없는 출력 숫자(`50,000`)도 원문 `5만`의 값과 비교한다.
3. **strict 단위 일치(권장):** 출력 숫자가 원문에 문자열로 있어도, 그 숫자가 단위가 붙은 금액 안에 있으면 그 값이 원문 금액 값 중 하나와 같아야 한다. `$11 million`(원문 `$11 billion`)·`KRW 5 billion`(원문 `5조원`)처럼 **숫자는 같고 단위만 틀린 오류**를 잡는다. 샘플 40건 오탐 0. DB 대리 측정에서 strict로 추가로 걸린 것은 대부분 실제 10배 단위 오류였다(부록).
4. **수 단어(근거 쪽만):** 영어 one~twelve·twenty·thirty·fifty·hundred·dozen, 서수 first~tenth, 한국어 첫·하루·이틀·사흘·나흘·열흘·두·세·네·다섯·열·스무를 근거 숫자로 추가한다. 출력 쪽 단어는 검사하지 않는다(→ "one teammate" 같은 파생 수는 못 잡는다. 규칙으로만 막음).
5. **근거 텍스트는 원문 제목 + 모델에게 준 발췌(2,000자)만.** 계획서의 "한국어 요약도 근거" 안은 빼기를 권한다: 한국어 요약은 같은 호출의 출력이라 같은 오류를 공유하고, 실제로 단위 오류가 많다. 확인: 1301에서 EN이 `$90 billion`으로 틀렸다고 가정하면 원문만 근거일 때는 기각, 한국어 요약(`900억 달러`)을 넣으면 **통과**(오류 세탁). 샘플 40건에서는 한국어 요약을 넣어도 오탐이 줄지 않았다(필요 없음).
6. **잡지 못하는 것(규칙·용어집·정독으로):** 단서 누락(약·이상), 파생 수를 단어로 쓴 것, 통화 바꿔치기(`5조원`→`$5 trillion` — 숫자·규모가 같아 통과; 원하면 "출력 `$` 금액은 근거에 `$`/`달러`/USD가 있어야 함" 통화 검사 추가 가능), 주체 바꿔치기(1325 — 출력 이름이 본문에 있으니 통과), 날짜의 월 이름.
7. **테스트 케이스:** 위 39개 경계 사례를 `englishCheck.test.ts`에 그대로 옮기면 된다(계획 1-4의 `1조 원`↔`KRW 1 trillion`, `$1.2B`, `GPT-5.1` 포함).

같은 검사기를 반대 방향(기존 `title_ko`+`summary_ko`의 숫자를 원문과 대조)으로 게재 1,232건에 돌렸다. 영어 출력이 아니므로 오탐률이 아니라 **규칙이 대규모에서 무엇에 걸리는지** 보는 용도다.

- 단순 V0: 214건(17%) 기각 → 최종 규칙(loose): 62건(5.0%), 그중 19건은 한국어 쪽 월 표기(`6월` ← "June", 영어 출력에는 해당 없음). strict: 77건.
- strict에서 단위 불일치로 걸린 17건 중 확인한 것은 대부분 **기존 한국어 가공본의 10배 단위 오류**였다: 1301 `$900B`→"900억 달러", 151 `$965B`→"965억 달러", 671 `$50B`→"50억 달러", 1055 `$30B`→"30억 달러", 1306 `753B`→"753억 파라미터", 1321 `27B`→"27억", 636 `12B`→"12억", 493 `$3.49 billion`→"3.49조원". loose에서도 걸린 1054 `155T`→"1,550억"도 같은 종류다. 반올림 2건(109 `$101M`→"1억 달러", 1258 `150억2700만`→"150억")은 엄밀히 규칙 위반이다.
- 범위 밖이지만 알려 둔다: **한국어 요약의 billion→억 환산 오류가 반복된다.** 세 줄 요약은 이미 코드로 걸러 내지만(brief.ts), 기사 본문 요약에는 같은 검사가 없다. 영어판 1-3 검사기를 한국어 가공에도 붙이는 것(기각 대신 notes 경고)을 Phase 1에서 함께 고려할 만하다.
