# Phase 4-2 클라이언트 색인 — 월별 분할·필드 축소 (2026-11-05)

대상: `feat/en-size-budget` `4c3d0ac` 위 `size-index-shards`. DB는 기준선과 같다(sha256 `0c359361…`, 게재 1,277건, 호 월 2026-06·07·10·11).
단위: KB = 1,000 B. "gzip"은 `gzip -9`로 잰 값이고, "전송"은 nginx(`docker/nginx.conf`, gzip 기본 수준)에서 브라우저가 받은 본문 크기다.

## 결정

1. **필드부터 줄인다.** 색인 화면이 쓰지 않는 필드를 빼고, 키 이름을 되풀이하지 않는 행(배열)으로 싣는다. 매체 이름·형식은 목록의 매체 표에서 찾는다.
2. **호 월별로 나눈다.** 기사의 호 월(`created_at` KST 날짜 = 호 날짜의 `YYYY-MM`)마다 조각 하나를 두고, 언어마다 목록(`manifest.json`)을 둔다. 검색 색인과 홈 색인 모두 같은 배치다.
3. **검색은 최근 3개월(`SEARCH_RECENT_MONTHS = 3`)만 먼저 받는다.** 그 이전 달은 필요할 때 받는다.
4. **홈 "더 보기"는 목록 하나로 끝낸다.** 홈 색인 기본 정렬은 최신순이 아니라 **화제순**(trending → 게시 시각)이다. 화제 지수는 줄지 않는 값이라 둘째 페이지부터 모든 달의 기사가 섞인다(현재 1~8쪽에 네 달이 다 나온다). 월별 조각만 두면 "더 보기" 한 번에 모든 달을 받아야 한다. 그래서 첫 페이지 다음 4페이지(120건, `FEED_HEAD_SIZE`)를 목록의 `head`에 싣는다. 그 너머로 펼치거나 필터·정렬을 걸면 지금처럼 모든 조각을 받는다.

## 파일 배치

```
public/search-index/<locale>/manifest.json   목록: schema·kind·locale·fields·total·sources·months[{month,count,v}]
public/search-index/<locale>/<YYYY-MM>.json  조각: 그 달 기사 행 배열(기본 정렬 순)
public/feed-index/<locale>/manifest.json     목록 + head(색인 머리 120행)
public/feed-index/<locale>/<YYYY-MM>.json
```

- 목록 URL은 `?v=<최신 호 날짜>-<누적 건수>`(빌드 버전), 조각 URL은 `?v=<조각 내용 sha256 앞 10자리>`다. 지난 달 조각은 내용이 그대로면 URL도 그대로다. 그래서 다음 날 빌드 뒤에도 브라우저 캐시를 쓴다(Pages 600초, 그 뒤 ETag 재검증).
- 행 필드(`FEED_ROW_FIELDS`)는 `id, source, title, summary, category, tags, trendingScore, importance, publishedAt, relatedCount` 순서다. 검색 행(`SEARCH_ROW_FIELDS`)은 여기에 `titleOriginal`이 붙는다. 목록의 `fields`가 코드와 다르면 읽는 쪽이 실패로 본다.
- 되돌리기는 `decodeRow` 한 곳에서 한다(`src/lib/indexShards.ts`). 컴포넌트와 필터는 IndexCard 모양만 본다. 만들기·쓰기는 `scripts/lib/indexShards.ts`가 맡는다.
- 조각을 합칠 때는 기본 정렬 비교자(`compareDefaultOrder`)를 쓴다. 이 비교자에 `id ASC` 동점 처리를 명시했다(SQL `orderByFor`도 같다). 지금 SQLite가 내던 순서와 같다(1,277건 전부 일치, 동점 36쌍). 합친 결과는 빌드 시점 누적 순서와 같다. 그래서 그 위에 거는 최신순·중요도순(안정 정렬) 결과도 예전과 같다.
- 단일 파일 `search-index.json`·`feed-index.json`은 더 만들지 않는다. export가 로컬 `public/`에 남은 사본도 지운다.

## 필드 변화 (1,277건)

| 색인 | 뺀 것                                                                                                               |     원본 B/건 |     gzip B/건 |
| ---- | ------------------------------------------------------------------------------------------------------------------- | ------------: | ------------: |
| 검색 | 원문 URL(28.5 KB gz)·묶인 보도 목록 → 개수(27.8 KB)·메트릭(1.3 KB)·매체 이름·형식(목록 매체 표로), 키 이름(행 배열) | 818 → **507** | 237 → **185** |
| 홈   | 매체 이름·형식, 키 이름                                                                                             | 574 → **429** | 155 → **150** |

- 숫자는 조각과 목록을 합친 값이다. 홈 목록(20.3 KB gzip)은 `head` 120행의 중복분이라 홈 B/건에서는 뺐다.
- 요약(`summaryKo`)이 검색 gzip의 40%다. 그래도 매칭과 결과 카드 둘 다에 쓰여 남긴다.
- 날짜 압축(`.000Z` 제거)이나 태그 사전은 gzip을 0.2~3%만 줄여 넣지 않았다. 태그 사전은 지난 달 조각을 목록에 묶어 캐시를 깨기도 한다.

## 검색 화면 (UX)

- 처음에는 목록과 최근 3개월 조각만 받는다. 최근 3개월은 최신 호의 달을 포함한 3개 달력 월이다(기사가 없는 달도 센다).
- 지난 달이 남아 있으면 결과 머리 건수 뒤에 범위를 밝힌다. 예: "“에이전트” 검색 결과 250건 · 2026년 9월 이후 기사 중".
- 결과 끝에는 1px 잉크 괘선 아래 한 줄 버튼을 둔다. 예: "**지난 기사에서도 찾기** · 2026년 9월 이전 기사 317건". 상자와 채움이 없고, 높이는 44px다. hover하면 낱말만 코발트가 된다. 누르면 지난 달 조각을 받아 같은 FlexSearch 문서에 더하고, 범위 문구와 버튼이 사라진다. 받는 동안과 실패 때는 같은 자리에 색인 상태 줄(다시 시도)이 선다.
- 받은 달에 결과가 0건이면 지난 달을 곧바로 받는다("지난 기사에서 찾는 중…"). 전부 받아도 없을 때만 "결과 없음"을 보인다.
- 한 번 받은 조각은 같은 탭에서 다시 받지 않는다. 다른 검색어로 바꿔도 그대로다.
- **함께 고친 버그:** FlexSearch는 필드당 기본 100건에서 결과를 잘랐다. 그래서 흔한 낱말은 일치 일부만 보였다. 예: "에이전트" 321건 중 186건, "모델" 432건 중 205건. 상한(`SEARCH_RESULT_LIMIT`)을 색인보다 크게 두었다. 그대로 두면 받은 달이 늘어도 건수가 늘지 않아, 범위 문구와 지난 기사 버튼이 거짓이 된다.

## 홈 화면

- 순서는 예전과 같다. 첫 30건은 정적 HTML이고, "더 보기" 1~4회는 목록의 `head`로 펼친다. 그 너머는 모든 조각을 받아 합친다.
- "남은 N건"은 처음부터 빌드 시점 누적 건수(목록 `total`과 같다) 기준이다.
- 필터·정렬 URL로 들어오면 목록과 모든 조각을 받은 뒤 결과를 그린다. 받는 동안에는 지금의 "불러오는 중" 상태 줄이 선다.

## 영어판이 들어오는 자리

- `src/lib/indexShards.ts` `INDEX_LOCALE`에서 `en: "ko"`를 `"en"`으로 바꾼다. 지금은 영어 페이지도 한국어 색인을 읽는다(Phase 3와 같다).
- `scripts/lib/indexShards.ts` `INDEX_BUILD_LOCALES`에 `"en"`을 더한다. 영어 기사 거르기(`indexArticlesFor` = `hasEnglish`)와 영어 행 인코딩은 이미 들어 있다. 행의 title·summary 칸에는 영어가 들어가고, 되돌리면 `titleEn`·`summaryEn`이 된다. 목록 매체 표에는 영문명이 들어가고, FlexSearch는 영어 필드를 색인한다.
- 크기 보고(`scripts/lib/sizeReport.ts`)는 `search-index/en/…`·`feed-index/en/…`을 영어로 센다.
