# Phase 2-3 한국어 숫자 오류 수정 목록

작성 2026-11-04 · 대상 `data/app.db`(로컬 `deploy/github-pages`, 마지막 수집 커밋 `e101a58` 11-04 호) · 수정 목록 [configs/backfill/ko-number-fixes.json](../../../configs/backfill/ko-number-fixes.json) · 검사·검증 스크립트는 세션 스크래치패드(커밋 안 함)

## 요약

- **경고 45건 → 실제 오류 24건 → 수정 38항목**(25개 기사, 제목 11 · 요약 27). 2-3 표본 검토([2-3-sample-review.md](2-3-sample-review.md))에서 사실 오류 #633 2항목을 더해 **40항목**(26개 기사, 제목 12 · 요약 28)이다.
  - 단위·값 오류 19건 + 모델 버전 오류 2건 = 1-3 목록 21건과 정확히 같다. 고치지 못한 건은 없다.
  - 경고 분류로는 파생 수·반올림이지만 값이 틀린 3건(#155·#475·#1237)을 **2026-11-04 사용자 결정으로 추가**했다.
  - 숫자 경고와 별개로 검토 중 본 **숫자 외 사실 오류 3건**(#417·#770·#1258)도 사용자 결정으로 고친다(3항목, 아래 별도 표). #633(2항목)은 백필 apply 뒤 표본 검토에서 더했다.
- 나머지 경고 21건은 고치지 않는다: 반올림 7 · 파생 수 10 · 기타(오탐) 4.
- 검증: 38항목 모두 `from`이 지금 필드값에 **정확히 1번** 나온다. 같은 필드의 여러 항목은 서로 겹치지 않아 어느 순서로 적용해도 1번이다. #633 2항목은 38항목이 적용된 지금 DB(백필 커밋 `41f27a7`)에서 같은 검사를 했다(제목·요약 각 1번, 고친 제목 41자). 적용 뒤 `checkKoreanNumbers`를 다시 돌리면 25개 기사 중 23건이 **경고 0건**이다. 남는 2건은 예상한 것이다.
  - #155 `100억`: 원문 발췌가 한 줄("it's funding news…")뿐이고 `decacorns`는 숫자로 읽지 않아 근거가 없다. 값은 맞다.
  - #1258 `150억`: `150억2700만원`의 반올림 경고다. 이 기사는 사실 오류(기간)만 고쳤다.
- 고친 제목은 모두 60자 이하다.
- DB는 그대로다(readonly로 열었고 `git status data/`가 깨끗하다). 게재 기사는 1,255건으로 1-3 측정 때와 같다. 11-05 이후 수집분은 이 목록에 없다 — 적용 때 `from` 불일치는 건너뛰지 않고 실패로 보여야 한다.

## 방법

- 게재 기사 전체(`summary_ko IS NOT NULL`, 1,255건)에 `checkKoreanNumbers`를 돌렸다. 근거는 파이프라인과 같다: `{title: title_original, content: content_raw.slice(0, MAX_INPUT_CHARS)}`(`enrichEvidence`).
- 경고 45건마다 원문 제목·발췌와 한국어 제목·요약을 나란히 읽고 분류했다. 환산 기준: million = 100만, billion = 10억(100 billion = 1,000억), trillion = 1조.
- 실제 오류(단위·값, 모델 버전)만 고친다. 반올림·파생 수는 고치지 않는다(2026-11-04 사용자 결정). 단, 그 분류로 경고됐지만 값이 틀린 3건은 같은 날 사용자 결정으로 넣었다. 표기는 기존 한국어 문체를 따랐다(`9,000억 달러`, `68억`, `14.5억 달러`).
- 수정은 숫자 부분만 바꾼다. 숫자 외 사실 오류 4건은 원문 발췌가 분명히 뒷받침하는 부분만 최소로 고쳤다(reason `사실 오류: …`).
